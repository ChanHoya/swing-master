## 상세 리스크 & 대응

### R01 — 포즈 추정 정확도 미달

**문제**: MediaPipe가 특정 촬영 각도 / 의상 / 조명에서 keypoint를 잘못 감지

**지표**: 포즈 추정 실패율 > 10%

**대응책**:
1. **사전 조건 검증**: 업로드 시 영상 밝기, 해상도, 인물 비율 자동 체크
2. **Fallback**: MediaPipe 실패 시 AWS Rekognition Pose Detection으로 전환 (비용 주의)
3. **가이드라인 강화**: 촬영 가이드 페이지 제공 (각도, 배경, 조명 예시 이미지)
4. **신뢰도 임계값**: visibility < 0.5인 keypoint는 회색 처리 (추정값 표시 지양)

---

### R02 — 분석 속도 30초 초과

**문제**: 포즈 추정(CPU) + LLM 호출 직렬 처리 시 30초 초과 가능

**지표**: p95 분석 시간 > 30초

**대응책**:
1. **병렬화**: 포즈 추정 완료 즉시 LLM 호출 시작 (asyncio gather)
2. **프레임 수 제한**: 전체 프레임 대신 핵심 4개 프레임만 추출
3. **캐싱**: 동일 업로드 재분석 시 캐시된 결과 반환
4. **스트리밍 응답**: 포즈 분석 결과 먼저 표시 → LLM 피드백 스트리밍
5. **알림**: 30초 초과 시 이메일/웹훅 알림 (비동기 처리)

---

### R03 — OpenAI API 비용 폭증

**문제**: 분석 1회당 GPT-4o 비용 ≈ $0.05~0.10. 트래픽 급증 시 예산 초과

**대응책**:
1. **비율 제한**: 익명 사용자 1일 1회, 가입 사용자 5회/일
2. **비용 모니터링**: OpenAI Usage 대시보드 + 월 예산 알림 설정 ($50)
3. **모델 다운그레이드**: GPT-4o-mini로 A/B 테스트 후 품질 충분하면 전환
4. **프롬프트 압축**: 불필요한 토큰 제거, 지표 소수점 1자리로 반올림

---

### R04 — 모바일 업로드 실패율

**문제**: iOS Safari / Android Chrome에서 대용량 파일 업로드 실패 (메모리, CORS, 타임아웃)

**대응책**:
1. **Presigned URL 직접 업로드**: 백엔드 경유 없이 클라이언트 → R2 직접 전송
2. **청크 업로드**: 10MB 단위 멀티파트 업로드 구현
3. **파일 압축**: 클라이언트에서 해상도/비트레이트 다운스케일 후 업로드
4. **재시도 로직**: 네트워크 끊김 시 자동 재시도 (exponential backoff)

---

### R05 — 저품질 영상 포즈 추정 실패

**문제**: 흐린 화면, 부분적 신체 노출, 역광 등으로 인한 추정 실패

**대응책**:
1. **업로드 전 영상 품질 검사**: 밝기 히스토그램 / 블러 감지 (OpenCV Laplacian)
2. **명확한 실패 메시지**: `docs/05_prompts.md` PROMPT-002 활용
3. **재촬영 가이드**: 실패 원인별 개선 가이드 팝업 제공

---

### R06 — LLM 피드백 품질 불일치

**문제**: GPT-4o가 JSON 포맷 오류 반환 또는 부적절한 피드백 생성

**대응책**:
1. **Structured Output**: OpenAI `response_format: json_object` 또는 `json_schema` 강제
2. **파싱 검증**: Pydantic 모델로 응답 검증, 실패 시 재시도 (최대 2회)
3. **품질 샘플링**: 1% 무작위 샘플 수작업 리뷰 워크플로 구축
