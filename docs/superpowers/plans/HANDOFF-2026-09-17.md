## 반드시 먼저 할 것 — 실제 스윙 영상으로 검증

**아직 한 번도 실제 영상으로 돌려보지 않았다.** 모든 테스트는 합성 좌표다.
저장소에 영상 파일이 하나도 없어서(`NewUI/uploads`는 PNG뿐) 검증을 못 했다.

측면(down-the-line) 스윙 영상을 구하면 가장 먼저:

```bash
cd backend && .venv/bin/python scripts/verify_axes.py <영상경로>
```

세 가지를 확인한다 — y축이 아래로 양수인가, 원점이 힙 중심인가,
스윙 중 어깨 수평각이 실제로 30도 이상 변하는가.

**실패하면 회전 지표(어깨/힙/X-팩터)의 부호가 뒤집힌 것이므로 그것부터 고쳐야 한다.**
코드는 정상으로 보이고 테스트도 통과하지만 숫자가 거짓인 상태다.

같은 영상으로 `detect_phases` 결과도 눈으로 확인할 것 (아래 참조).

## 진행 방식

사용자가 **절충 방식**을 지시했다:

- 계획서에 완전한 코드가 적힌 전사 성격 Task(11, 13, 15, 16) → 인라인으로 직접 처리
- 판단이 필요한 Task(12 파이프라인 배선, 14 LLM 역할 축소) → 서브에이전트 구현 + 리뷰

사유는 비용이다. Task 0+1에 에이전트 호출 4회가 들었고 세션 누적이 $149를 넘었다.

## 테스트 실행 시 주의

**`pytest` 출력을 `tail`/`head`/`grep`으로 파이프하지 말 것.** 종료 코드가 가려진다.
이 세션에서 그 탓에 실패하는 테스트를 커밋한 적이 있다(`9b5de92` → `e76810a`로 수정).

```bash
cd backend && .venv/bin/pytest tests/ -q > /tmp/pt.txt 2>&1; EXIT=$?; tail -5 /tmp/pt.txt; echo "EXIT=$EXIT"
```

## 이월된 미결 사항

### 1. 단계 탐지를 실제 영상으로 재검증해야 한다 (우선순위 높음)

Task 10에서 이식한 휴리스틱의 결함을 발견해 고쳤다. 원래 코드는 탑을
"임팩트 이전 모션 최솟값"으로 찾는데, **어드레스의 정지 구간도 모션이 0에 가까워
그쪽을 탑으로 집는다.** 합성 스윙 프로파일에서 탑을 14프레임 빗나갔고
`takeaway`와 같은 프레임으로 붕괴했다.

탑을 어드레스~임팩트 구간의 손목 y 최솟값으로 직접 찾도록 바꿨다
(`app/services/swing/phases.py`의 "탑 =" 주석 참조).

**이식이 아니라 개선이므로 원본과 동작이 다르다.** 실제 영상에서 7단계가
눈으로 보기에 맞는지 반드시 확인할 것.

### 2. 최종 리뷰로 미룬 Minor 지적 4건

- `test_metric_value_is_frozen`이 `FrozenInstanceError` 대신 bare `Exception`을 assert
- `PoseSequence`가 `frozen=True`지만 numpy 배열은 in-place 변경 가능
- `test_x_factor_equals_shoulder_minus_hip` 픽스처의 `hip_rotation`이 0이라
  2dp 반올림 누적오차(~0.02도)를 잡지 못함
- `head_movement`/`weight_shift` 신뢰도를 address+impact 프레임에서만 재는데,
  최대 변위는 중간 프레임에서 나올 수 있음 (계획서 `_METRIC_PHASES` 설계 자체의 갭)
